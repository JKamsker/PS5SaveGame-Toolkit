## Summary

UnrealGvas is a useful, lossless GVAS inspector and scalar editor, but its three verified PS5 title families expose little playable meaning and two deliberately block progression writes. A substantially better experience combines a bounded generic property explorer with title-specific character, inventory, equipment, progression, collectible and photo views, showing evidence and valid limits beside each control. The first blocker is a policy-compatible, correctly licensed Hogwarts Kraken/SQLite path; the second is unresolved Jedi and Sackboy integrity; the third is missing PS5-verified semantic mappings, reference-data rights and controlled console validation. Deliver useful read-only overlays first, then narrowly verified existing-value edits, and only later structural inventory changes. Complex titles should eventually have their own document implementations over a reusable GVAS component, with explicit framework-owner agreement on how that component is shared.

## Baseline state (historical evidence)

- Research date: 2026-10-28. Read the mandated project documentation, plugin source/tests, SDK, relevant Core/UI code and [issue #1](https://github.com/JKamsker/PS5SaveGame-Toolkit/issues/1). Repository HEAD observed during research was `885b2f8eec6ecbb9353794c3623b50ec45343e41`; observations concern the shared working tree, which can contain concurrent changes. No repository files were changed and no build/test/npm commands were run. Existing scratch downloads were reused; downloaded code was read, never executed. Independent standard-library Python probes ran with `-I`; reproducible findings are in scratch `inspect.py`, `verify_evidence.py` and `verified-evidence.json`, without embedding private save data in this plan.
- **Existing implementation:** `plugins/UnrealGvas/SaveToolkit.Plugins.UnrealGvas/UnrealGvasPlugin.cs` identifies actual raw GVAS or a supported envelope containing it, at engine confidence; filenames alone do not establish support. `Gvas/GvasParser.cs`, `GvasTag.cs` and `GvasPrimitives.cs` already support header versions 1–3, legacy/UE5.4 tags, scalar/FString/FText source values, tagged structs, struct arrays, primitive arrays/maps/sets and selected native structs. This is not a proposal to implement those features again. Legacy tag size and static index are separate uint32 values, not one uint64 size.
- **Preservation/editing:** `Gvas/GvasFile.cs` replaces original scalar spans, updates enclosing sizes, reparses/compares the decoded result and supports exact undo. Unknown payloads, header details, encodings and tails are retained; no collection insert/delete/reorder exists. Struct-valued map/set entries without a schema, removal records and image/database byte arrays remain opaque. Extend the representation to retain schemas/removal records rather than silently rebuilding them.
- **Presentation:** `UnrealGvasDocument.cs` has an overview, lazy 100-node property pages and top-level scalar search tables; IDs are ordinal paths, stable under scalar length changes but unsuitable for arbitrary insertion. Visible property names containing CRC/checksum/signature disable all writes. This is conservative protection, not proof that other documents lack integrity metadata. Limits already include 128 MiB, 100,000 nodes, depth 64 and 1,048,576 FString units.
- **Hogwarts Legacy / PPSA01603:** 34 archive records, 17 distinct payloads; UE 4.27.2/package 524/72 custom versions. `SaveGameList` is slot metadata; `HL0000`–`HL0014` contain compressed databases. Independently walked every UE chunk in HL0010: `RawDatabaseImage` has 35 blocks declaring 4,534,280 decoded bytes, `RawExclusiveImage` 33 blocks declaring 4,231,176; both use `8C 06` streams and consistent outer lengths. Public converter platform-tag patterns match this sample. **SQLite rows were not decoded or inspected**, and the two images must not be assumed identical mirrors.
- **Jedi: Fallen Order / PPSA02199:** six archive records, three distinct payloads; UE 4.25.0/package 518/56 custom versions. Settings are editable, gameplay/backup documents are read-only. Independently decompressed both actor arrays to their declared 2,580,619/2,471,665 bytes; each begins with a headerless tagged `ActorRecords` stream. Stored CRCs `253EB7D0`/`3A3A9C96` differ from IEEE CRC32 of both compressed (`97B6B113`/`AD68AFA4`) and decoded (`19B1D711`/`6A4BFDA3`) streams. Existing `JediChecksumResearchTests.cs` covers additional unsuccessful ranges/variants; that suite was inspected, not rerun here.
- **Sackboy / PPSA01288:** 20 archive records, six distinct payloads; UE 4.25.1/package 518. Independently confirmed `CollectabellsStored` and `TotalCollectabellsCollected` are IntProperty values 445/445 and 322/322 in the two General snapshots; `Checksum` is UInt32Property, and `UnlockedWorlds` is an enum array with one entry. This verifies storage, not gameplay limits or safe editing. Image-set companions contain Name-to-struct maps and texture metadata. One `LevelImages_04` zlib stream at `0x6E4` expands 12,144 bytes to 131,072; no PNG/JPEG was found. Pixel format/swizzle remains unverified on PS5.
- **Boundaries:** samples for Kena/PPSA01802 contain custom versioned region data, not GVAS; PPSA02343 is Profile JSON. Atomic Heart/PPSA10695 uses custom SaveExtension framing and belongs to the existing AtomicHeart plugin. PPSA16064 Character is JSON; Global settings are byte-minus-one JSON, not XOR 1. Do not inherit uncertain game-name labels or claim any of these because a filename resembles an Unreal save. Existing regression tests explicitly decline them. Only `docs/formats/PPSA01288.md` exists among these title-specific format notes; missing documents are an evidence gap.
- **Tests already present:** `GvasSampleTests.cs`, `GvasFormatTests.cs`, `GvasVersionTests.cs`, `GvasEnvelopeTests.cs`, `SackboySampleTests.cs`, `JediChecksumResearchTests.cs`, `UnrealGvasConformanceTests.cs`. README reports exact round trips across all 60 claimed records/26 distinct payloads and previous passing test runs; those are historical reports, not fresh results from this planning task. Real wrapped PS5 fixtures and console reload validation remain absent.
- **Framework capabilities to reuse:** `src/SaveToolkit.Sdk/Views/ViewNode.cs` already has tabs, lazy sections, tables, fields, actions, images/assets and hex. `FieldSpec.cs` has scalar ranges, enum labels/descriptions and flags. `BoundSaveDocument.cs` supports scalar bindings, rollback and derived changes; cross-field rules require a custom atomic edit implementation. `ISaveDocument.cs`/`Saves/SaveSet.cs` already expose sibling files and multiple existing-file outputs. No new generic multi-file contract is needed just to update an existing slot-metadata file.
- **Concrete framework gaps:** `Core/Sessions/DocumentSession.cs` records scalar undo; non-undoable structural actions clear history. There is no opaque document memento for reversible insertion/deletion. `Core/Editing/ViewIndex.cs` has no canonical field-reference node. `web/src/components/document/TableView.tsx` renders text/field cells, so arbitrary image cells are not a usable inventory grid yet; `fields/FieldControl.tsx` uses a native enum select without icon/search support. Global lazy-graph search, reference-data import/context and before/after action previews are missing.
- **Avoid stale requirements:** `web/src/components/document/DocumentEditor.tsx` and `src/SaveToolkit.Api/Endpoints/WorkspaceEndpoints.cs` already permit original-file download when editing is disabled; the plugin README's read-only-download request is outdated. `Core/Export/WorkspaceExporter.cs` already overlays sibling outputs and rejects competing writes; it reopens dirty primary documents, but title-specific validation of every rewritten companion needs explicit coverage. Identical backup twins are handled differently from independent save generations: never mirror Jedi `Backup00` merely because its name says backup.

### Integrity / crypto

- **Hogwarts codec gate:** [powzix/ooz, `0503806`](https://github.com/powzix/ooz/tree/05038060aa68f9187ae9923b2388ca8db40e58d1) has GPL-3.0-or-later source headers and warns its decoder is not fuzz-safe; [q3k/pyooz](https://github.com/q3k/pyooz) is a native GPL binding. [Oodle.NET, `6a6b78b`](https://github.com/NotOfficer/Oodle.NET/tree/6a6b78bc3c145eddd6a3ae139fd95d6678049e12), MIT, wraps a proprietary native runtime; it is not managed Kraken. [oozextract, `8acaeb2`](https://github.com/lvlvllvlvllvlvl/oozextract/tree/8acaeb2bc375dd56c413a83aae4e87156136fdac) declares MIT in Cargo.toml but calls itself an ooz port: review ancestor provenance before relying on that declaration; Rust/native/Wasm does not satisfy the current managed plugin contract. No candidate is cleared and production-proven for this plugin.
- **Other codec leads:** [LibProsperoPKG, `748eabf`](https://github.com/SvenGDK/LibProsperoPKG/tree/748eabf1b7d17819528cabf367d8e27109d8fce3), GPL-3.0, includes managed Kraken work for PFS but has unsupported entropy/recursive paths and different surrounding framing; neither licensing nor completeness permits treating it as a solution. [Epic Oodle documentation](https://dev.epicgames.com/documentation/unreal-engine/oodle-data) describes stored/uncompressed modes but does not prove our PS5 reader accepts an expanded stored-Kraken rewrite. Decide between independently implemented managed decoding with cleared provenance, or an explicit owner-approved host codec boundary. Never silently ship a game DLL or relax plugin rules.
- **SQLite gate:** [Microsoft's provider documentation](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/custom-versions) confirms Microsoft.Data.Sqlite uses SQLitePCLRaw/native SQLite. A normal package addition is therefore not a fully managed/no-I/O solution. [csharp-sqlite, `104a79e`](https://github.com/CsharpDatabase/csharp-sqlite/tree/104a79e839d182bf64139041e1fbaf9ff9a27602) has an MIT license but is an old managed port with unproven .NET 10, memory-VFS and modern-save compatibility. Evaluate a managed read-only reader using the [official file format](https://www.sqlite.org/fileformat.html) if needed; do not improvise a writable SQL engine. An approved byte-in/byte-out host service is an architectural alternative, not an existing capability. No SQLite key/encryption evidence was found in the still-compressed sample payloads.
- **Jedi/Sackboy:** no reviewed source resolved either checksum. Existing failed CRC32/CRC32C experiments are valuable exclusions, not a solution; storage type/name does not prove the algorithm. Obtain controlled changes, locate coverage boundaries, test byte order/seed/serialization/custom folds with independent vectors, and validate recomputed integrity against several untouched captures before editing. Never zero/bypass the checksum or enable only a subset of fields on a document whose integrity covers unknown bytes.
- **Wrappers and crypto:** the three claimed PS5 sample families have plain outer GVAS. Existing read-only RFC1950/Astroneer envelope support follows [RFC1950](https://www.rfc-editor.org/rfc/rfc1950) and [Astroneer author research](https://gist.github.com/MartyMacGyver/ebeb8f803ef66be87c7c7d95d000ab42); the reported game-specific window constraint is not a universal Unreal rule. Recompression needs real wrapped PS5 fixtures, including lengths/Adler/window tests. Outer console decryption/signing is outside this plugin. No inner encryption was observed; absence of hidden per-game integrity has not been proven. Atomic Heart SHA-1 knowledge belongs to its separate format and cannot be transferred by publisher/engine association.

## Vision

The landing page identifies the exact title/schema version, save role and confidence, then shows a readable character summary with unresolved evidence clearly marked. Tabs become Character, Inventory & Equipment, Skills, World & Quests, Collectibles, Photos and Advanced as each title has meaningful coverage; omit irrelevant tabs. Every item shows its canonical ID, name, category, description, icon provenance, owned count, effective cap and evidence for editability; unknown IDs stay visible and unchanged.

Hogwarts gets currencies/consumables, gear comparison and slots, XP/talent accounting, spell/recipe/lock states, collectible checklists and later a calibrated map. Jedi gets a read-only actor-derived character/skill/stim/cosmetic/world overview before any gameplay edits. Sackboy gets Collectabells, costume/wardrobe/world/level progress and a correctly decoded photo gallery; currency/world edits wait for integrity repair. Map labels are useful without coordinates; pins wait for verified coordinate transforms and licensed/user-supplied map layers.

Bulk actions operate on known existing entries: fill owned consumables to verified caps, apply an equipment preset from owned gear, or reset a pending edit group. Preview every target and derived change, reject mixed-validity batches atomically, and support full undo. Quest/trophy unlocks, granting absent items and mass completion remain separate late capabilities requiring prerequisite/reward/event evidence; a counter reaching its maximum is not proof of a completed game event.

Use small composable schema readers, binding builders and validators inside the existing plugin first. Generic GVAS retains engine-confidence fallback; a future Hogwarts/Jedi/Sackboy plugin may claim title confidence only with positive version/class/schema checks. Hogwarts' dual SQL databases and Jedi's actor graph justify separate documents once mature; Sackboy can begin as a schema overlay. Do not reference another plugin assembly under the SDK-only rule: request an approved reusable GVAS library/extraction before splitting. Kena needs separate custom-format research, while JSON and AtomicHeart remain with their existing owners.

## Phased plan

**Phase 1 — Useful read-only overlays and schema foundations. Size M; risk medium.** Goal: make current bytes understandable without weakening integrity gates.

- [ ] Add plugin-local version/class/property-signature schema selection and explicit evidence labels; retain the generic view for unmatched schemas. Model raw vs game-semantic confidence separately.
- [ ] Extend bounded traversal for schema-known Name-to-struct maps/sets, including removal records and opaque fallback. Preserve all ordering/indices/GUIDs/tails; start with Sackboy costume/image maps. Add canonical typed paths and stable element identity without changing serialized names.
- [ ] Show verified Sackboy currency/lifetime fields and world counts, then decode photo metadata/zlib and independently test PS5 pixel order, dimensions and swizzle against a known screenshot. Serve a bounded PNG gallery with current ImageNode/GetAsset.
- [ ] Read Jedi's already-decodable headerless actor stream into bounded trees; index candidate player/skill/inventory/collectible actors without guessing which numeric field is currency or XP. Keep the entire gameplay document read-only.

## Acceptance criteria

- [ ] Existing generic capability is retained: all 60 claimed archive records/26 distinct payloads reopen and no-op serialize byte-for-byte; tests distinguish duplicated twins from independent evidence. Unknown headers/tags/padding/tails/removal entries remain unchanged. Kena/JSON/AtomicHeart regressions stay unclaimed.
- [ ] New layouts have source/version/schema evidence, bounds checks, malformed-input rejection, real fixtures where available and safe opaque fallback. Deep maps/actor streams cannot bypass byte/node/depth budgets; representative opening targets remain approximately two seconds, with measured hardware/sample details rather than an unmeasured claim.
- [ ] Generic and curated values share a canonical binding/identity. Duplicate labels/IDs are disambiguated by actual serialized identity; an unknown or ambiguous row is never edited by name similarity, guessed offset or largest numeric value.
- [ ] Every newly supported edit has a known serialized type, intended game effect, effective range and prerequisite/ownership rule; evidence distinguishes Verified/Inferred/Unknown. Missing catalog rows/icons/caps cannot cause dropped items, fake names, guessed caps or hidden default writes.
- [ ] Hogwarts decodes every chunk to an independently matching output, validates prefix/SQLite framing, fingerprints both databases and documents their roles. No-op retains original compressed bytes. Writes preserve unrelated GVAS data, satisfy database integrity/reference checks, fit actual size limits, and reopen with expected rows and no lost unknown tables.
- [ ] Stored-Kraken output, if chosen, has explicit PS5 load/save/reload and growth-budget proof; a PC tool's successful extraction or compression-mode documentation alone cannot enable it.
- [ ] Jedi/Sackboy checksum algorithms reproduce stored values across multiple independent unchanged captures and controlled pairs with independent vectors. Corruption is rejected. Gameplay writes remain disabled for unsupported versions/coverage; there is no checksum bypass or falsely “safe” subset.
- [ ] Sackboy image previews match a known PS5 screenshot's dimensions, orientation and colors; unsupported formats remain opaque. Gallery loading is bounded; existing photos remain byte-identical because previews do not rewrite them.
- [ ] Existing-value writes precede insert/delete support. Atomic multi-field/preset edits expose every derived change, reject invalid combinations without partial mutation, and undo back to exact original bytes, including integrity/compressed outputs and changes made after lazy expansion.
- [ ] Structural edits, if enabled, have unique element identities, required defaults/references/capacity rules, reversible transactions and retired stale IDs; repeated undo/redo/reopen cannot address the wrong item. Unsupported structures remain read-only.
- [ ] Every modified companion is explicitly owned and validated; no conflicting output wins silently, no independent backup is overwritten as a presumed twin, and slot selection/menu metadata remains consistent in game.
- [ ] Each enabled gameplay capability passes backed-up PS5 load, intended-effect observation, save, exit and second reload with no unintended progression/ownership changes. Quest actions additionally prove prerequisite/reward/event behavior; trophies/entitlements are not inferred from a flag.
- [ ] Catalog/code/media provenance is recorded and compatible with the chosen distribution route. No proprietary DLL, uncleared HLSGE code, unlicensed scaffold code, private sample or copyrighted icon pack is bundled by assumption; plugin code performs no filesystem/network I/O.
- [ ] Implementation work later runs the existing conformance/format/sample suites and relevant new checks, with samples absent producing skips rather than failures. This research task itself makes no fresh build/test/console-pass claim. Changes remain in the authorized plugin scope unless framework owners separately undertake the explicit requirements.

## Open questions & risks

- Who will own and fund the licensed managed codec/database work, or approve a narrowly defined host boundary? Without R1/R2, Hogwarts can still improve its generic/metadata experience but cannot honestly offer decoded inventory editing.
- What are the separate purposes and overlap rules of RawDatabaseImage and RawExclusiveImage on these exact PS5 builds? Different decoded lengths are verified; authoritative/merged/mirrored semantics are not. A broad update-both strategy can corrupt independent state.
- Is stored/raw Kraken accepted at every PS5 database/chunk boundary and within save-slot quotas? A larger structurally valid file can still exceed platform/game allocation. Actual compression may remain necessary.
- What exact serialization/seed/coverage produces Jedi Crc32 and Sackboy Checksum? Existing negative searches reduce hypotheses, not the possibility of hidden per-actor or per-container integrity. Two uncontrolled General snapshots cannot establish causality.
- Which emitted actor/map keys persist across reloads, new games, language/build changes and DLC? Ordinal IDs are adequate for existing scalar editing, not structural semantics; runtime declarations alone do not establish on-disk layout.
- Are all relevant resource/skill/quest effects materialized in a save, or driven by runtime events/rewards? PC editor claims and maximum counters cannot establish safe PS5 completion. Treat unexpected behavior as a reason to narrow that action, not expand generic bypasses.
- Can game versions/locales be identified reliably beyond the Unreal header/custom versions? A changed schema with familiar property names must not silently inherit an incompatible overlay or cap table.
- Which reference assets can be redistributed, and which require user-owned extraction? A permissive extractor/editor license grants no rights to Hogwarts/Sackboy/Jedi text/icons. No download/upload or secret material is needed for this plan; later sample sharing must remain private and scoped.
- The toolkit edits decrypted inner files; platform resigning/import availability and account-linked behavior remain external human prerequisites. No support claim for other platforms or non-GVAS titles follows from engine/publisher similarity.
- Only currently inspected working-tree behavior is described. Concurrent repository changes, stale README claims and later upstream commits require a focused recheck before implementation; use the pinned sources and recorded byte evidence as the baseline.
