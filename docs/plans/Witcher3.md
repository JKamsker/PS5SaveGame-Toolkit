# Witcher3 — improvement plan

## Summary

The `witcher3` plugin already has an Experimental, preserving writer for PPSA04018 saves with SAV3 tuple `64 / 23 / 163`, plus progression, Crowns and existing-stack quantity controls. A substantially better editor would show localized inventory/equipment, character skills/mutations, Gwent, Roach/stash, recipes, and readable quest/world progress. Independent checks found substantial unused structure already in every supplied save, including 102 skills, 16 skill slots and Gwent collection data. The three main blockers are the narrow early-game sample corpus, missing PS5 runtime validation and dependency rules, and a versioned reference-data/asset route with explicit redistribution rights. Deliver rich reads and conservative existing-record improvements first; item creation, build presets and story changes need separate evidence gates.

## Research findings

All sources checked 2026-10-28. **Verified** means the specified byte check succeeded; **Inferred** fits a source but lacks an independent game observation; **Unknown** is untested. Container compatibility does not prove gameplay-schema compatibility.

### Integrity / crypto

- All supplied gameplay bytes are already decrypted and raw-LZ4-decodable. Signature, one chunk, 3,084-byte header, exact expansion, directories and `.req` contents were rechecked. No encryption key or resigning secret is required for **these input bytes**; console restoration/resigning remains outside the plugin.
- [LZ4 block specification](https://github.com/lz4/lz4/blob/dev/doc/lz4_Block_format.md): raw blocks do not carry frame checksums. The researched SNFH writers repair sizes/offsets without an outer-checksum step; samples have no unexplained nonzero reserved header words or outer trailer. This is observed framing evidence, **not proof that every inner structure/future schema lacks integrity dependencies**. Preserve opaque magic values rather than inventing a CRC.
- Existing writers repair descriptors, SAV3 pointers, PORP/BLCK/SS lengths and conservative name growth, then reparse. Before new growth, identify every containing count/length/reference. Existing patch support does not establish arbitrary ROTS, SBDF, attachment or equipment writing.
- [timrosenbach/w3-save-repair, `507bac61525964cd7d7ecf8cc6617de9541faa80`](https://github.com/timrosenbach/w3-save-repair/tree/507bac61525964cd7d7ecf8cc6617de9541faa80), MIT Python, treats a specific PC Remastered Fact-ID corruption/chunk-table overwrite. It can replace fact names and lose original meaning: not a generic repair action for this plugin. No matching corruption observed. Useful bounds/header-capacity research; never blindly raise limits or rewrite opaque facts.
- Missing knowledge: fact words/value/time/expiry semantics, handle/item links, equipment/mutation caches, journal/quest-thread/world consistency, mixed SXAP versions and modern PS5 schemas. `.w3strings` version keys concern optional resource extraction, not save encryption. No private credential values were read.

## Vision

- **Overview:** actual supported schema/build, Geralt versus Ciri, region, progression, separate currencies, DLC/mod pack status, pending changes and per-feature confidence.
- **Character:** initially read-only vitality/stamina/toxicity/derived stats; named skill trees, ranks/costs, active slots, mutagen groups and mutation prerequisites. Later validated respec/build presets preview all points/slot/cache effects.
- **Inventory/equipment/stash/Roach:** searchable localized names and raw IDs, icons/descriptions, category, quantities, durability, instance attributes and upgrades, with explicit ownership. Combat slots and horse gear are separate from internal appearance/scabbards. Bounded refill/repair targets supported existing ordinary items, excluding quest/internal records by default.
- **Alchemy/crafting:** known/missing recipes/diagrams, expansion filter and ingredient checklist; existing-material refill first, recipe grants after dependencies are understood.
- **Gwent:** owned/missing copies by faction, sources/missables, leaders/decks and separate collection/deck/achievement rules. Tracker first, narrow edits later; adding cards must not promise trophies.
- **World/quests:** journal/objective tree, sourced facts, Places of Power/signposts/discoveries and eventually regional maps. Discovery, completion, depletion and rewarded state are distinct. Story presets are preconditioned multi-system transactions, never an unexplained completion flag.
- **Review:** semantic old-to-new changes, exclusions/dependencies, one-step undo and export companion coverage. Clearly identify raw input versus pending curated state and retain the expert explorer.

## Phased plan

Sizes estimate implementation after evidence arrives: **S** a few focused days, **M** roughly one to two engineering weeks, **L** several weeks or more. Sample collection, rights decisions and console feedback can dominate elapsed time.

### Phase 1 — compatibility matrix and immediate rich reads (M)

- [ ] Record patch, title/region, outer/nested tuple, DLC, NG/NG+ and mods per independent fixture; retain exact editing guards and preservation logic.
- [ ] Add composed typed readers for observed ability arrays, recipes and richer existing-item metadata, retaining original spans/unknown fields. Show saved IDs/ranks/links before localization.
- [ ] Decode collection pairs within the actual Gwent manager boundary; separate collection/deck lists and handle structurally valid empty collections.
- [ ] Show journal resource/GUID/status paths and read-only facts with opaque words/timestamps; consume all bounded encodings exactly. Do not equate an inferred fact sum with quest completion.
- [ ] Add reviewed small name mappings, missing-pack placeholders and unresolved-ID reporting.
- Evidence: current measurements plus current-patch/later-game/Ciri/DLC/NG+ fixtures (R1/R14/R15). Existing SDK nodes support useful work immediately.
- Risk: medium, limited by read-only scope. Gate: reproduce all measured counts and exact no-op bytes; distinguish encoded values from inferred semantics.

### Phase 2 — useful existing inventory and conservative writes (M)

- [ ] Join a matching item catalog; show descriptions/icons/categories, raw IDs, slots, durability and attributes. Separate instance-generated values from template defaults; do not fabricate live weapon stats.
- [ ] Verify the durability encoding/range from blacksmith repair pairs before fixed-size repair edits.
- [ ] Apply versioned stack rules and a bounded existing-stack refill excluding quest, equipped, unique/internal records unless explicitly supported.
- [ ] Resolve horse/stash entities through actual handle identities; show Geralt, stash and Roach separately once each path is evidenced.
- [ ] Preview and apply one atomic, undoable batch; keep Crowns bound to the same inventory record across views.
- Evidence: exact catalog joins; purchase/use/drop/repair pairs; Orens/Florens; stash and horse-gear changes; PS5 reload/re-export (R1–R5/R14).
- Risk: medium. Gate: plausible game constraints, intended values survive console load and unrelated state stays unchanged.

### Phase 3 — progression, skills and mutations with dependencies (L)

- [ ] Decode skill enums, rank/cost/path spending, prerequisites, slots, mutagen links, research costs and stat/cache state for the supported schema.
- [ ] Model level/XP/points including already granted rewards and dependent slot/stat changes. Keep current raw stored-level edits explicitly limited until the safe workflow is proven.
- [ ] Enable one existing skill-rank/slot change only after a native purchase/equip pair and reload establish required updates. Preserve core skills, sentinels and unrelated ability state.
- [ ] Implement respec/build presets only with complete refunds, path-point, ability/slot and vitality/toxicity effects. Repeated application must not duplicate refunds; reject unsupported/modded profiles.
- [ ] Gate mutation research/unlocks separately on DLC quest prerequisites and consumed mutagen/point rules. Keep Ciri separate.
- Evidence: buy/rank/equip/respec/level-up pairs, B&W pre/post unlock/research, matching installed scripts/definitions (R1/R3/R14/R15/R18).
- Risk: high: a parseable save can contain a broken character. Gate: PS5 save/reload, combat, world transition, respec and fresh native-save tests.

### Phase 4 — Gwent, recipes and world reads, then narrow edits (M–L)

- [ ] Finish card names/copy expectations, source/missable rules, leaders/decks and base/HoS/B&W coverage, keeping unknown states explicit.
- [ ] Compare one card purchase/win and deck change; permit existing-count/deck changes only after collection/reward/quest dependencies are understood. Absent-record creation waits for Phase 5.
- [ ] Show known/missing recipes/diagrams, named map discoveries/signposts/Places of Power using stable native IDs. Tables precede the map.
- [ ] Prove one ordinary recipe grant or signpost discovery before category-wide unlocks. Place-of-Power changes must not grant points twice.
- Evidence: card/deck/cutoff, recipe-learn and location-discovery/use pairs; matching data (R14–R17).
- Risk: medium for reads, high for writes. Gate: tracker matches the native game and each edit has byte and game evidence.

### Phase 5 — structural inventory and coherent equipment transactions (L)

- [ ] Implement insertion/split/merge/deletion; block referenced, equipped, quest/internal records until cleanup rules are complete.

- [ ] Integrate structural undo/redo, exact state restoration, stable IDs and lazy-view invalidation before normal-user add/remove UI.
- [ ] Test descriptor capacity, multi-chunk growth/shrinkage, retained chunk-boundary limits, dictionary/ID exhaustion, duplicates and malformed nested records. Refuse unsupported growth without overwriting reserved headers.
- Evidence: add/remove/split/merge/equip sequences, enchanted/NG+ gear and large late-game inventories (R1/R14/R15); structural history R10/R11.
- Risk: high. Gate: unrelated-payload preservation audit and repeated PS5 loads/saves, beyond matching item counts.

### Phase 6 — curated story presets and interactive world view (L; separate gate)

- [ ] Build journal/fact/thread dependency graphs from matching legitimate data and controlled transitions; preserve opaque fact words/time entries until explained.
- [ ] Show decision summaries first; allow only small preconditioned presets whose journal/fact/spawn/reward updates are all understood.
- [ ] Add region maps with native IDs/coordinate transforms and linked details; map presentation does not authorize gameplay unlocks.
- [ ] Preview and revalidate every story transaction; retain unsupported stages read-only. No unrestricted “complete all quests.”
- Evidence: exact branch/objective pairs plus later quest continuation/world revisit and owner testing (R16–R19).
- Risk: very high, potentially unbounded; some decisions may remain read-only permanently. Gate: documented end-to-end gameplay outcome per allowlisted preset.

## Open questions & risks

- Which patch produced `64/23/163`, and what do its words mean? Do current PS5 5.x saves share PC inventory extensions/skill indexing? [CDPR PlayStation support](https://support.cdprojektred.com/en/witcher-3/playstation/sp-technical) now lists 5.01/Remastered topics; that does not extend the calibrated plugin schema.
- Which skill/mutation/stat records are definitions, acquired state, caches or live values? Sixteen core skills and 13 mutation records include initialization/sentinels; displayed entries must not imply purchased state or double refunds.
- What does the nonzero uint16 in 183 later-save fact entries mean? Are value/time/expiry semantics version-dependent? Exact-consumption parsing establishes framing, not field meaning or a checksum.
- uint16 quantities do not establish legal caps or every money encoding. Multiple Crowns stacks/alternate components may be legitimate. Never merge by display name or silently omit unknown records from correctness audits.
- Horse-manager inventory may represent stash rather than Roach equipment. Resolve actual ownership and transfer pairs. Appearance/scabbards/hidden gear also look equipped and need protection.
- DLC/NG+/Ciri/mods change definitions/initialization. [Current CDPR mod guidance](https://support.cdprojektred.com/en/witcher-3/nintendo-switch/gameplay/issue/3001/cross-platform-mod-support-how-to) describes changed XML/script/localization compatibility and matching-mod cross-progression requirements. Latest-PC catalogs are not automatically correct for older PS5 saves.
- Journal visibility, objective statuses, facts, threads, spawned entities and rewards can diverge while files still load. Some story states may never be safely editable; readable decisions do not prove safe transitions.
- MIT catalog/code licences do not automatically cover flavor text, icons, map tiles or scripts. Keep rights/provenance decisions explicit and maintain an asset-free mode.
- Tool claims/version support change; code was pinned/read only. Commercial cheats, runtime memory pointers, a converter demonstration or identical backups never establish PS5 edit compatibility.
- This deliverable validates research reads, not an implementation. No writer was changed and no console accessed; the implementation round must turn each feature's evidence gate into tests and documented native observations.
