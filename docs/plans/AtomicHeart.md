## Summary

AtomicHeart (`atomic-heart`, PPSA10695) is a careful ReadOnly SaveExtension inspector: it validates the outer container and SHA-1 but cannot inspect gameplay records. A substantially better editor would show P-3's resources, backpack/storage, named weapons and upgrades, Polymer abilities, blueprints, and regional collectible/progress checklists with evidence-backed limits. The top three blockers are a policy-compatible Oodle decode/write route, an unverified Atomic Heart record grammar, and the absence of controlled PS5 saves plus matching reference data. Oodle stored frames are a promising compressor-free experiment, not an established PS5 solution. Ship useful reads first, then existing-value edits, and defer structural and story changes until independent console observations establish their dependencies.

### Integrity / crypto

- **Verified outer integrity:** SHA-1 of all but final 20 bytes matches both files; [RFC 3174](https://www.rfc-editor.org/rfc/rfc3174) is the algorithm reference. No secret key or outer MAC is indicated by this check. Recompute after permitted changes. This does not establish absence of inner hashes/duplicated state or replace console envelope signing.
- **Codec identification:** `Oodle` string is explicit; `8C 06` and decoder references suggest Kraken. [Epic Oodle Data](https://dev.epicgames.com/documentation/en-us/unreal-engine/oodle-data) distinguishes method/effort and documents copy-only level 0. Packaging documentation is **not a guarantee** about this SaveExtension fork. Verify stream flags, checksum bits, reset/history behavior and exact output lengths with a decoder.
- **Commercial route:** [RAD Oodle](https://www.radgametools.com/oodle.htm) offers an evaluation SDK/contact route; [Epic integration docs](https://dev.epicgames.com/documentation/unreal-engine/using-oodle-in-unreal-engine?lang=en-US) describe engine integration. Neither establishes independent toolkit redistribution rights for oo2core. Even a user-local DLL needs a permitted-use/architecture decision; never fetch mirrors or bundle under a wrapper licence. Native/proprietary integration requires an explicit managed-plugin policy exception.
- **Stored-mode experiment:** future minimal reviewed encoding should preserve original compression on no-op, update frame totals/outer array lengths/SHA-1 after edits, and pass independent decode plus PS5 load → resave → decode. Growth could be substantial (~1.75 MB versus 124 KB compressed here); check container capacity. Neither stored encoding nor recompression was tested here.
- **Unknown:** exact inner fork, decoder revision, identities, inner integrity/duplicated state and game-side constraints. Do not seek keys before evidence indicates encryption. PAK keys for asset extraction are a separate issue from the decrypted save; handle any supplied keys without exposing values.

## Vision

- **Overview:** slot/build/region, checksum, readable duration, sublevel and supported decode/edit capabilities. Distinguish slot summaries from live player state.
- **P-3 / Polymer:** verified stored health/energy, Neuropolymer, learned skills/equipped abilities; prerequisite-aware detail and build-cost preview. No invented RPG attributes.
- **Inventory/storage:** named searchable backpack and NORA storage, optional local icons/descriptions, quantities and stack/capacity warnings. Distinguish material counters, instances, ammo stacks and quest items. Unknown IDs stay visible/read-only.
- **Weapons/crafting:** owned instances, loaded versus reserve ammo, installed modules/levels, learned blueprints; valid alternatives filtered by build/DLC/prerequisites.
- **World/journal:** regional Testing Ground, blueprint, Chirper and quest checklists; optional offline map after coordinate and image-rights verification. Useful read-only before progression writes; no promised trophy unlocks.
- **Bulk actions/presets:** refill selected existing stacks to verified limits, add a chosen material amount, apply a validated existing-item loadout/skill preset with cost/prerequisite preview. Report every changed value and support undo; no blanket integer maximization.
- **Review/raw:** semantic before/after values, disabled-edit reasons, source/build/confidence and bounded record/property/hex exploration. Retain original download and directory export.

## Phased plan

Phase 1 — admissible decoding and record inspection (L).
- [ ] Audit codec provenance/licences; choose permitted managed implementation or obtain explicit architecture/policy decision for injection. Stay ReadOnly without a suitable route.
- [ ] Decode 14 chunks under work/size limits; assert per-chunk/aggregate lengths, reset/history assumptions and retain original slices.
- [ ] Identify byte-array prefix, tagged UObject boundary, manual records and fork deviations using pinned upstream sources.
- [ ] Build bounded read-only indexes with stable parent/class/name paths, byte spans and unknown retention; reject impossible counts/references.
Evidence: decoded sample, independent decoder agreement and annotated boundaries. Risk: codec rights, fork differences/resource exhaustion. Exit: reproducible structural read with exact consumption or explicit unknown ranges; no edits.

Phase 2 — gameplay identity and useful named reads (L).
- [ ] Obtain AH-R3 controlled pairs and AH-R4 reference data; map Neuropolymer/material counters, then owned inventory and quantities.
- [ ] Align player/GameInstance/level identities across saves, not row indexes; distinguish live state from metadata/world loot.
- [ ] Add resource, backpack/storage, weapon/module and skill/blueprint reads with raw IDs and evidence/confidence.
- [ ] Compare displays with known in-game observations; document duplicate representations and zero-versus-absent/unspawned entries.
Evidence: independent labelled PS5 states and exact ID joins. Risk: runtime/save IDs differ, derived effects and DLC variants. Exit: multiple independent observations match each supported feature.

Phase 3 — compatible writer, then scalar edits (L).
- [ ] First test a semantic-no-change stored-frame/recompression candidate on a disposable copy; preserve byte-identical serialization for untouched documents separately.
- [ ] Rebuild necessary framing/stream portions, preserve unrelated plain spans and reusable independently decodable compressed chunks; update lengths and SHA-1.
- [ ] Decode/reparse output; compare intended semantic changes and all untouched spans; establish actual inner integrity.
- [ ] Enable small existing Neuropolymer/material/ammo deltas with proven limits and atomic coupled validation; report derived changes for undo.
- [ ] PS5 load, observe, spend/use, resave, restart and reload each operation; widen scope only after results. Human controls Stable promotion.
Evidence: independent decode, console acceptance and persistence. Risk: growth, hidden copies/references/loader restrictions. Exit: narrow proven existing-value writes, no creation.

Phase 4 — upgrades/loadouts/presets (L).
- [ ] Establish instance identity, blueprint ownership, part compatibility, costs/levels, skill prerequisites and equipped slots from controlled changes.
- [ ] Modify existing items/learned nodes first; determine derived stat/capacity updates.
- [ ] Add accessible details/icon picker, prerequisites, selected bulk actions and complete preview with table fallbacks.
- [ ] Define explicit spend/refund semantics and atomic presets; test unavailable DLC/unknown-ID retention.
Evidence: buy/refund/upgrade/equip pairs and post-load persistence. Risk: dangling equipment references/derived effects. Exit: every preset has PS5 validation and reversible changes.

Phase 5 — progress explorer and separately gated structural writes (L).
- [ ] Correlate objectives, discovery, collectibles and Testing Ground rewards; add map only after transform/coordinate and rights checks.
- [ ] Keep quest writes disabled until dependencies and event-granted rewards are understood; release checklist reads independently.
- [ ] Study add/remove/move/split using empty/new-stack/drop pairs: IDs, arrays/lengths, references, footprint/capacity/storage and equipment.
- [ ] Require structural undo/redo and transactional rollback before creation/removal; reject unsupported states.
Evidence: boundary/branching/structural pairs plus console results. Risk: softlocks/event rewards/reference damage. Exit: reads independently releasable; writes only for proven operations.

## Open questions & risks

- Does compressed content begin with DataBytes' int32 length, and how much upstream manual grammar survives? Requires bounded decoding.
- Can a provenance-cleared managed decoder be delivered reasonably? MIT metadata on a self-described GPL-code port does not settle derivation rights. Native/service use requires an explicit policy decision.
- Does PS5 accept stored frames, larger declared compressed lengths and approximately 14-fold payload growth? PC same-engine success is only a hypothesis. Compressor-free writing still needs decoding.
- Inner hashes, version-dependent structs and duplicate state remain unknown. Do not import Hogwarts' no-checksum assertion into Atomic Heart.
- Are resources owned by player/GameInstance/components and duplicated in equipped actors? Runtime APIs name the domain, not its persistent layout.
- Do skills/upgrades store points, costs, effects/capacity and prerequisite state separately? A valid parse can still yield an unusable build or omit event-granted rewards.
- Are saved IDs paths/FNames, GUIDs or indices? Runtime catalogue seeds are not PS5 mappings; debug/DLC names can exist without equippable content.
- Integer width/9,999 cheat values do not establish legal stack caps. Need data plus measured boundary behavior.
- One early Vavilov snapshot cannot establish later/NG+/DLC/patch formats. Identical backups must not inflate the evidence count.
- Community data is incomplete, inconsistent and often copyrighted. Prefer raw IDs/authored verified labels, with separately cleared or user-local enrichment.
- Genuine framework gaps concern optional codec/private-data injection, rich catalogue/map UI and reversible structural commands. Scalar editing and original export do not require replacement contracts.
