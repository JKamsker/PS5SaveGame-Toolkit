## Summary

The `astro-playroom` plugin already edits the observed PS5 allocation without normalizing its unusual XML-like text, and exposes coins, progress flags and unnamed collectibles. A substantially better editor would provide a named PlayStation museum catalogue, a world-by-world missing-collectible checklist, meaningful progress controls and version-aware special-bot support. The first blocker is the lack of controlled saves tying individual collectible IDs to locations and linked progression changes. The second is the absence of newer-schema samples containing special-bot and additional-artifact fields. The third is the lack of console reload evidence establishing accepted values, dependency rules and persistent effects. Most initial improvements fit the existing SDK; rich collection layouts and reviewable bulk operations need focused framework/UI work.

## Research findings

### Existing editors/tools (same game, other platforms)

- **Platform scope:** [Sony product page](https://www.playstation.com/en-us/games/astros-playroom/) (accessed 2026-10-28) lists PS5. No official PS4/PC/Xbox/Switch edition, corresponding save parser or transferable layout was established. Native PC emulation of PS5 software does not constitute a separate PC save format. Sony page/assets are proprietary; link for product facts, do not bundle artwork. Title/platform verified externally; only PPSA01325 bytes verified locally.
- **Strongest actual editing lead:** [PS5_Jailbreak special-bot thread](https://www.reddit.com/r/PS5_Jailbreak/comments/1wemi58/astros_playroom_special_bots_dont_show_up/) (September 2026; search-indexed replies visible even where the direct page collapses them). A contributor describes editing `Common/ArmadilloFeatureRegionLock`, `ArmadilloReleaseDateInDecimal`, `ArmadilloUnlockPhase` and `_SetNext` companions in `memory.dat`, updating the backup and reloading; another reports the notification and first bot becoming available. This is an anecdotal **event-enablement** recipe, not proof of rescued-bot state, complete dependencies or Astro Bot transfer. 010 Editor is used in text mode; no reusable binary template/parser is supplied. Posts have no permissive code licence; use cited observations and independently implement only after sample verification. Transfer confidence: medium for existence of newer text fields, low for the complete recipe; **none of those Armadillo fields exists in our two snapshots**. Do not transplant offsets or insert them.
- **Save Wizard exclusion:** [official FAQ](https://www.savewizard.net/faqs/) explicitly limits PS5-console compatibility to PS4-game saves; native PS5 saves are unsupported. Commercial/proprietary, no implementation to port; transfer confidence none for this title. No sample comparison applicable.
- **Apollo:** [patch database at `273f032b4c31c017fed5c1588f209b8faf87ba6c`](https://github.com/bucanero/apollo-patches/tree/273f032b4c31c017fed5c1588f209b8faf87ba6c), [PS4 app at `29da777575c288e677b342fa21b6cfc45283ef6a`](https://github.com/bucanero/apollo-ps4/tree/29da777575c288e677b342fa21b6cfc45283ef6a), [library at `cf1f1823a534f35d03fc41ef2c5b641e7fde30d4`](https://github.com/bucanero/apollo-lib/tree/cf1f1823a534f35d03fc41ef2c5b641e7fde30d4). GitHub metadata reports GPL-3.0 for all three. The database root lists PS1/2/3/4/PSP/PSV/DC, no PS5 directory; recursive path searches found no Astro/PPSA01325/PPSA21564 match, which does not exhaust text inside every patch. Generic [savepatch documentation](https://bucanero.github.io/apollo-lib/savepatch.html) is not ASTRO format evidence. No ASTRO patch or algorithm established, no port proposed; GPL code would require a compatible distribution strategy rather than satisfying the guide's permissive-dependency rule. Transfer confidence none established; not tested against our bytes.
- **Misleading near match:** [PS5-Trophy-Unlocker at `9232262c29ea330d5e7fc5098be4b28b36829fbf`](https://github.com/NikoBellikJR31/PS5-Trophy-Unlocker-/tree/9232262c29ea330d5e7fc5098be4b28b36829fbf) and its [ASTRO release](https://github.com/NikoBellikJR31/PS5-Trophy-Unlocker-/releases) advertise trophy/UDS operations. - **Names/categories:** start with the 50 existing Artifact keys, 96 Puzzle keys and 18 Prop keys. Use an independently authored JSON catalogue keyed by exact saved group/key plus a schema fingerprint; include display name, category, world, sublevel, optional original hint, source URL/revision and per-mapping confidence. - **Descriptions:** original short hardware/collection descriptions are practical; verbatim in-game flavor strings need a rights decision. No complete permissively licensed localization/string-table dump was established. English first, localized labels as separately sourced mappings; IDs remain language-independent.
- **Limits:** flags are booleans, not inventory quantities; one catalogue entry has one ownership state. Neither public guide counts nor the existing signed-integer bound proves the coin cap. No equipment, weapon stacks, character-sheet system, skill tree or conventional quest log is evidenced in these saves; do not fabricate those screens. Model level/boss/event milestones as progression.
- **Icons/maps:** no complete, cleared, saved-ID-indexed asset pack established. Default to original generic console-category/puzzle glyphs with text and optional user-owned local images. A user-configured fetcher, if ever added, belongs in a host ingestion pipeline with permitted sources/terms and local caching; it is not a licence workaround. An original schematic world diagram can precede any game map; no exact map/puzzle coordinates are verified.
- **Catalogue versioning:** public pages include newer hardware absent from the 50-entry sample set. Totals must come from existing supported records, not a current wiki's global count. Record page revisions when converting research into distributable data.

### Integrity / crypto

- Local bytes are directly readable at `0x400`; numeric element names rule out a strict standard-XML serializer. The observed payload needs no discovered decryption key or compression codec. This does not address platform container encryption/signing, which remains outside the plugin.
- Fresh byte checks confirm zero preambles and padding, root/NUL separation and CRC32 values above. `AstroIntegrityEvidenceTests.cs` investigates CRC32/ISO-HDLC, Adler-32, byte sums and length/end words across specified root/text/NUL ranges and both endiannesses. The tests' source was inspected, **not rerun**; no checksum field has been identified. Zero headers and candidate failures do not prove the absence of all integrity mechanisms.
- [zlib checksum documentation](https://zlib.net/manual.html#Checksum) (v1.3.1 manual) and [RFC 1952](https://www.rfc-editor.org/rfc/rfc1952) specify algorithm conventions used in local investigation, not an ASTRO checksum. zlib code is permissively licensed under the zlib licence; no library/code port is necessary. Independently implemented tests already exist. Candidate calculations match local evidence; applicability as stored checksums is unverified.
- The community's successful text-edit report is evidence that at least one newer layout can reload after some text changes. It is not our console validation and does not prove arbitrary flag combinations, coin values or insertion of missing tags are valid. Reopen validation catches syntax/preservation failures, not semantic corruption.
- Unknowns to resolve experimentally: ownership versus cinematics, milestone flags versus UDS counters, gatcha bonus rewards and notification state, persisted special-bot event phases, and any format/integrity changes in newer allocations. Preserve the 77-byte suffix as opaque; stale-overwrite residue is an inference. Keep unsupported layouts rejected until characterized.

## Vision

- **Dashboard:** schema-support status, coins with established safe presets, collection totals split into artifacts/pieces/dioramas, world clear status and prominent unresolved-mapping counts. Separate verified meaning from Experimental write status.
- **Museum:** one row/card per artifact with a name, family, original short description, optional licensed/user image, acquisition area and ownership. Display cinematics as a distinct advanced state, never silently equate it with collected. Show raw key and provenance in details.
- **Worlds & puzzles:** four named worlds plus CPU Plaza, Labo and endgame; show missing-only and acquired-only filters, readable sublevel names and progress bars. Map physical puzzle locations only after controlled mapping; an original schematic remains useful without coordinates.
- **Gatcha/Labo:** distinguish artifact prizes, puzzle pieces and prop/diorama records. Offer a calculated coin top-up for a chosen number of attempts using the sourced 100-coin cost, bounded by an independently validated coin policy; random blank prizes mean this is not a guaranteed completion budget.
- **Progress:** readable visited/clear/boss milestones with evidence-based prerequisites; notifications and one-time reward counters stay advanced/read-only until their relationships are tested. No leaderboard editing or trophy unlock promise.
- **Special Bots:** show absent/unsupported for old schemas; on supported newer saves distinguish event enabled, capsule discovered, rescued and transfer-ready only where independently established. Never insert absent tags into an old save as a shortcut.
- **Actions & review:** preview exact named changes for selected collectibles, one world or a validated preset; apply atomically as one undo step. Prefer existing-value ownership changes and narrow coin actions before whole-world unlocks. No blanket “100%” button until all relevant dependencies are known.
- **Advanced:** existing lazy raw tree, schema diagnostics and a focused semantic/byte change report. Every unmapped value and unknown suffix survives untouched.

## Phased plan

Phase 1 — Named, read-first catalogue and schema report. **Size M; risk low.**
- [ ] Inventory exact existing IDs, stable paths and group counts; define a schema fingerprint from structure/key sets, not guessed patch version.
- [ ] Create independently authored, sourced artifact/world aliases; give ambiguous aliases Inferred confidence and retain raw keys. Keep save-derived evidence separate from source licences.
- [ ] Replace the flat view with artifact/puzzle/prop sections, saved-record totals, mapped/unmapped counts and clear absence messages. Keep unsupported semantics read-only in new curated controls.
- [ ] Add mapping collision/missing-key checks, no-op preservation checks and source/licence manifest validation using current samples and synthetic allocations.
Evidence needed: current bytes are sufficient for raw counts; game screenshots/catalogue capture needed to verify labels. Delivery can use current tables/sections with no SDK extension and no copyrighted art.

Phase 2 — Controlled mapping and the first validated edits. **Size M; risk medium.**
- [ ] Capture single-event before/after pairs: one named artifact, one puzzle per ambiguous boundary, one prop prize, one normal coin gain/spend, one stage clear and one boss clear. Record build, action and in-game UI state.
- [ ] Diff balanced trees by stable IDs, then inspect all changed bytes and unrelated background changes; repeat an event on a separate slot where feasible.
- [ ] Establish coin persistence/range behavior and IsGot/cinematics/notification/UDS dependencies; test one existing collectible edit and one narrow coin edit independently.
- [ ] Enable only supported changes with batch-level invariant checks and full rollback; retain mature preservation code.
Evidence needed: AP-R1/AP-R2/AP-R3/AP-R5. Export/reopen alone is insufficient. Do not promote to Stable without human console evidence.

Phase 3 — Collection browser and carefully scoped actions. **Size M; risk medium.**
- [ ] Add names/categories/world filters, missing-only browsing, optional images/details and readable confidence/provenance.
- [ ] Add selected-entry collection actions and per-world presets only for dependency groups proven in Phase 2. A cinematic policy must be explicit and validated, not an automatic all-true rule.
- [ ] Preview all primary/derived changes, apply through one validated batch and return every ValueChange for one-step undo/redo. Coin top-up must validate arithmetic, capacity and observed limits.
- [ ] Verify dashboard totals, searches, filters and lazy views refresh after edits/actions/undo, including preserved original text spellings.
Evidence needed: mapped location data and dependency matrix; AP-R8…AP-R13 improve UX. Text tables plus parameterized ActionNode are a workable initial fallback.

Phase 4 — Newer special-bot/artifact schema support. **Size L; risk high.**
- [ ] Obtain labeled old/new update pairs and all event-state transitions; recheck allocation, root grammar, padding and integrity before extending detection.
- [ ] Add explicit compatible-schema profiles; expose unknown/new keys without assigning community values. Map additional existing artifact records independently.
- [ ] Distinguish event eligibility, phase scheduling, rescued-bot state and transfer state using controlled evidence. Start read-only, then edit existing fields only after console tests.
- [ ] Investigate paired Astro Bot import behavior as optional research; do not add sibling-game writing without a separate brief and its own evidence.
Evidence needed: AP-R4/AP-R5/AP-R6. No schema insertion/add-remove support is required for this phase; absent features remain absent.

Phase 5 — Completion planner, original world diagram and release hardening. **Size M–L; risk medium/high.**
- [ ] Add original schematic navigation and location-linked missing lists only for mapped pieces; provide original hints or licensed pack content.
- [ ] Offer completion presets only over verified existing-state dependency groups, with visible exclusions for unknown events and leaderboard/trophy state.
- [ ] Run plugin conformance/format tests, Core export regression checks and focused UI verification in an authorized implementation workspace; optional-sample tests must skip cleanly.
- [ ] Record human reload, intended effect, another gameplay action, resave/re-dump and clean second load for each supported action/schema family. Update README, confidence and limitations; human alone decides Stable.
Evidence needed: AP-R1…AP-R7 plus review UX. Structural creation/removal and cross-title editing remain separate future work; do not invent a need for inventory-row APIs.

## Acceptance criteria

- [ ] Implementation remains within the plugin folder; separate SDK/Core/UI changes have independently owned scope. No private saves, extracted assets or account metadata are committed.
- [ ] Every advertised mapping has an exact saved key, supported schema, source/provenance and confidence; physical puzzle locations are independently verified rather than guessed from prefixes.
- [ ] Both existing snapshots retain 50 artifacts, 96 puzzles and 18 props with correct original acquired counts. New schemas use their own actual record sets; guide totals never cause insertion/removal.
- [ ] Unknown records, whitespace, numeric tags, attributes, opaque suffix, padding and original value spellings survive byte-identical no-op and undo-to-original serialization across all supplied supported samples.
- [ ] Each write serializes, reparses and changes only intended spans plus necessary displacement/zero fill; new integrity handling, if discovered, has independent vectors and corruption tests.
- [ ] Atomic edits/actions reject invalid values, missing prerequisites or allocation overflow without partial changes; every derived change appears in the outcome and one-step undo/redo restores the full validated state.
- [ ] Named ownership changes never silently set cinematics, notifications, UDS counters, leaderboard state or absent bot fields. Each dependency change needs captured evidence and visible review.
- [ ] Current samples show special-bot support as unavailable. Newer schemas stay read-only until captured event/rescue evidence and independent reload tests justify each supported operation.
- [ ] Missing/acquired filters, table search, totals, thumbnails/details and raw views stay consistent after direct edits, actions, undo/redo and lazy expansion; keyboard controls have meaningful names.
- [ ] Reference packs work offline, identify their schema and licence/provenance, and keep copyrighted game media out of default distribution unless cleared. No plugin performs network or filesystem I/O.
- [ ] Plugin conformance and focused format/action tests pass during implementation; sample-dependent tests skip when absent. Existing Core export checks confirm same-generation identical backups mirror and divergent backups remain preserved.
- [ ] Views stay bounded, lazy where useful and honest about Unknown/Inferred meanings; no bogus inventory/equipment/quest system or 100%/trophy guarantee is presented.
- [ ] A human verifies each claimed gameplay edit/action on PS5 through load, intended effect, further gameplay, resave and second load. README records build/action/results, unresolved limits and exact sources before any Stable promotion.

## Open questions & risks

- Why do several internal puzzle prefixes split 5/3 while physical stages contain 4/4? Possibilities include shared boundary allocation or internal naming; none is verified. This specifically blocks accurate per-sublevel completion counts and maps.
- Does `IsCinematicsPlayed` only suppress the pickup presentation, or also gate museum placement/rewards? Is ownership alone sufficient for a safe grant or revoke? Revoke/reset actions need separate validation and should not be assumed symmetric with grants.
- Which notification/reward/UDS values are derived, consumed once, or authoritative? `World` also contains internal/test/menu names; do not curate every saved IsCleared flag as a player-accessible world.
- What patch versions produced the old samples? Structure provides a support fingerprint, not a reliable exact version. Human-supplied build labels are needed.
- What is the accepted coin cap, clamp/wrap behavior and PlayCount meaning? Public gatcha pricing establishes cost, not currency range. Artificially large values are not justified by serializer capacity.
- Are newer bot event phases regenerated from PSN/time/region state? The community recipe includes timezone and `_SetNext` fields; it does not establish minimal changes or long-term consistency. Never require account secrets for this research.
- What does Astro Bot actually read for transfer, and when? Same studio/brand does not establish shared files, IDs, integrity or safe simultaneous rewriting.
- The 77-byte suffix may be overwrite residue, but erasing or interpreting it would abandon the proven preservation policy. New formats with nonzero padding remain unsupported until independently understood.
- Public wiki content mixes versions and sometimes games. There is no established permissively licensed complete catalogue/string/icon dump. Rights and localization work can be bounded by shipping original text/glyphs first.
- A successful parser round trip can still produce a semantically broken game state. Lack of a known checksum also means syntactically valid input corruption may be undetectable. Maturity and field confidence must describe those separate limits.
- Research used existing scratch material and fresh read-only byte checks; downloaded third-party code/binaries were not executed. No repository files were modified and no tests/builds, commits, pushes or external posts were performed.
