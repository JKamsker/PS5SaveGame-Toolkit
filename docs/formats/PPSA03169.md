# PPSA03169 — Elden Ring (Japanese title ID)

> **Historical reconnaissance — 2026-10-28.** Measurements and unknowns below belong to the
> original research pass. Later parsers, writers and policy decisions supersede its implementation
> leads; see [current plugin status](../PLUGINS.md) and each plugin README for supported behavior.

**Hard; raw PS5 memory allocation.** [Title-ID mapping](https://prosperopatches.com/PPSA03169) identifies Japanese Elden Ring. SFO is generic; filename/size alone would not identify the game.

Only `sce_sdmemory/memory.dat`, 28,967,040 bytes, and an identical backup exist. At zero: LE `0x2C9C01CB`; sentinel `7F 7F 7F 7F` at `0x08`; LE 7/8 at `0x10/0x18`. First-MiB H=0.2045 indicates large zero/sentinel regions. No PC .sl2/BND header at zero, GVAS/DSSS framing or validated first-4KiB zlib stream. An allocator/slot-index wrapper is **inferred**, not mapped. Do not call the whole file encrypted from its name.

[ClayAmore/ER-Save-Editor](https://github.com/ClayAmore/ER-Save-Editor) (Apache-2.0) supports PC and PlayStation SaveWizard exports, with useful character/inventory maps. [er-save-manager](https://github.com/Hapfel1/er-save-manager) supplies more current FromSoftware research (licence and raw-PS5 support not audited). Neither support statement proves this memory.dat layout works.
