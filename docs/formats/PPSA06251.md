# PPSA06251 — Star Ocean: The Divine Force

> **Historical reconnaissance — 2026-10-28.** Measurements and unknowns below belong to the
> original research pass. Later parsers, writers and policy decisions supersede its implementation
> leads; see [current plugin status](../PLUGINS.md) and each plugin README for supported behavior.

**Blocked on save-specific encryption/framing.** [Title-ID listing](https://platprices.com/gb/game/90768-star-ocean-the-divine-force) identifies the game; SFO only repeats PPSA06251. SAVEDATA/SYSDATA names alone are not identifying.

SYSDATA_00000.DAT is 5008-byte system state; fifteen SAVEDATA_000xx.DAT files are gameplay candidates. First gameplay is 115,856 bytes. Gameplay representatives share first block `56 25 A1 6C A3 B7 C8 56 69 61 A0 FF 78 53 E3 4F`, but their next block differs. Near-uniform H≈7.998 and 16-byte-aligned lengths support a block-transform/encryption hypothesis; **not proof of AES/ECB**. No known frame or validated zlib stream. System first byte 0x5D does not establish LZMA.

[Original PC cheat-table thread](https://opencheattables.com/viewtopic.php?t=480) concerns runtime editing, not PS5 save parsing; licence not established. [Original PC asset research](https://zenhax.com/viewtopic.php%40t%3D17636.html) discusses CPK-extracted XOR/SLZ7 assets: useful negative distinction, not save cipher evidence. No applicable permissive PS5 save decryptor was established by these searches.

Next: controlled slot/option pairs and save-specific serializer/decryptor research. Keep read-only until cipher, decoded structure, compression and integrity validate. Reusing an asset XOR or exposing guessed offsets would risk the entire save.
