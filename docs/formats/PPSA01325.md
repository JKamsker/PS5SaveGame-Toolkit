# PPSA01325 — ASTRO’s PLAYROOM

> **Historical reconnaissance — 2026-10-28.** Measurements and unknowns below belong to the
> original research pass. Later parsers, writers and policy decisions supersede its implementation
> leads; see [current plugin status](../PLUGINS.md) and each plugin README for supported behavior.

**Easy for a preserving text editor.** [Title-ID mapping](https://prosperopatches.com/PPSA01325) identifies the game; SFO only says Saved Data. `sce_sdmemory/memory.dat` is the actual game document within a fixed 1 MiB allocation.

Verified: the representative first `0x400` bytes are zero; `<PreInstall>` begins at `0x402`, `<Common>` at `0x411`; text ends at `0x7776` followed by NUL. Its 785 opening tags include PlayCount, NumCoin, progress and boss flags. This is **XML-like, not valid standard XML**: numeric tag `<1073741839>` causes ElementTree rejection at line 1007, column 3. A strict XML serializer is inappropriate. No integrity field was verified; zero preamble does not prove absence of checksums.

[An original bot-unlock report](https://www.reddit.com/r/PS5_Jailbreak/comments/1wemi58/astros_playroom_special_bots_dont_show_up/) describes newer memory.dat text flags; it supplies anecdotal editing evidence, not licensed parser code. These samples contain no Armadillo tag, so those newer offsets/fields must not be transplanted. No game-specific reusable parser was established by the searches.

Next: tokenize the custom tags, patch existing primitive value spans and preserve allocation padding. Start with NumCoin or a boolean, compare both generations, and establish any integrity/length handling before an in-game edit test. Field names are verified; detailed gameplay effects/ranges remain unknown.
