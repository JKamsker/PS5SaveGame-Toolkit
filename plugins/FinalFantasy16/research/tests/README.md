# Offline regeneration characterization

Run from the repository root with Python 3 (standard library only):

```powershell
$env:SAVETOOLKIT_ARTIFACTS='C:/Users/Jonas/repos/private/JKamsker/PS5SaveGame-Toolkit/artifacts'
$env:SAVETOOLKIT_TEST_TEMP='D:/Temp/saveeditor/test-scratch'
$env:TEMP='D:/Temp/saveeditor/test-scratch/review-importer-golden-finalfantasy16'
$env:TMP=$env:TEMP
New-Item -ItemType Directory -Force -Path $env:TEMP | Out-Null
python -I -B -m unittest discover -s plugins/FinalFantasy16/research/tests -v
```

The tests never download data or execute upstream layout text. Each regeneration
runs the actual tool in a temporary plugin tree or redirects its output pack into
scratch. Source files and committed reference packs are never overwritten. These
tests are separate from the .NET plugin suite; they require no runtime changes or
Python dependency in the application.

## Functions, inputs and goldens

| Original function | Pinned inputs | Exact output comparison |
| --- | --- | --- |
| `apply_game_assets.main` | Committed `research/game-assets.json`; 145 WebPs checked against its SHA-256/lengths; freshly generated published/ability bases | All nine JSON artifacts across `ffxvi.published.en`, `ffxvi.abilities.en`, `ffxvi.maps.en`; stdout and a second idempotent pass |
| `build_layout_catalog.main` | Three retained `inputs/nex-layouts/*.layout` texts at `d3ad0627a29af168916ad574dadbca6759e2ac48`, checked against the tool's existing LF SHA-256 pins | All four JSON artifacts in `ffxvi.nex.en`, including manifest hashes; stdout |
| `summarize_corpus.summarize` (via the existing CLI) | External `PPSA10665_saves_dec.zip` and `PPSA13803_saves_dec.zip`, checked against `research/corpus-summary.json` archive SHA-256 values; committed published item IDs | Complete `--summary` stdout against `research/corpus-summary.json` |
| Same corpus function, without private data | Invented records and deterministic ZIP metadata constructed in `corpus_inputs.py` | Complete stdout against `goldens/corpus-synthetic.json`; summary mode against that golden with only individual records omitted |

Base regeneration uses the original `build_published_catalog.py` with the five
committed CSVs and their existing revision/hash pins, plus `round2-naming-audit.json`;
`build_ability_catalog.py` reads committed `abilities.source.tsv`. The media test
deletes all nine copied output JSON files before running either base builder.
It cannot accidentally pass by only decorating the already shipped catalogues.

Expected text artifacts are read in their committed UTF-8/LF format (CRLF checkout
conversion is removed only from the expected files). Actual generated files are
compared as bytes without normalization. The subprocess harness configures stdout
as UTF-8/LF before running the unchanged CLI, matching the committed evidence
format on Windows as well. No JSON reserialization or selected-field comparison
is used for the artifact goldens.

The diagnostic cases pin validation order and existing partial-write behavior:
layout hash checks precede directory creation; malformed skill annotations retain
earlier map/summon files; asset name mismatches precede record/manifest writes;
the aggregate media budget runs after pack writes. CRC-valid synthetic corruptions
exercise framing, version, allocation and preservation checks independently.

## Regeneration limits

Private archives stay external; no save bytes or extracted sample data are
committed. When either archive is absent, only the private-corpus test skips with
an explicit reason. The synthetic corpus, layout and media tests still run fully
offline. The private test fails on an incorrect archive hash. With the owner's
pinned archives available, all tests must pass with zero skipped.

The original PNG/JPEG downloads and retrieved HTML pages are not retained offline.
Re-fetching, selecting excerpts, and Pillow/WebP preprocessing are outside these
three functions and cannot be regenerated by this suite. The deterministic media
stage is fully characterized from the committed excerpts, processed WebPs and
base sources; it checks every processed image against the ledger. This does not
claim equivalence of a future image encoder or changing source website.

The corpus synthetic golden contains only invented paths, hashes and aggregate
metadata. It was captured using the original, unrefactored tool after an initial
placeholder golden failed. It is not evidence of a behavioral defect or console
acceptance. Existing committed artifacts provided the other goldens before any
function was split.
