# Offline importer characterization

Run separately from the native plugin suite, from the repository root:

```powershell
$env:TEMP = 'D:/Temp/saveeditor/test-scratch/review-importer-golden-eldenring'
$env:TMP = $env:TEMP
New-Item -ItemType Directory -Force -Path $env:TEMP | Out-Null
python -I -B plugins/EldenRing/Evidence/tests/test_importers.py -v
```

Python 3.14 and Pillow **12.2.0 / libwebp 1.6.0** were used for the baseline.
`requirements.txt` pins Pillow; install it before running tests if necessary. The tests never
install dependencies or download inputs. They reject an encoder-version mismatch rather than
silently skip or bless new image bytes. All outputs, intermediate images and extracted fixtures
go into a temporary directory and are removed afterward. A socket guard forbids network access.
The harness redirects the existing CLI output globals; it never writes to the runtime pack folders.

## Pinned source fixture and rights

`fixtures/clayamore-inputs.zip` contains **15 original upstream text files**, 68,495 bytes compressed.
These are source tables and the complete MIT notice, never saves or extracted game binaries.
Source: [ClayAmore / ER-Save-Editor, 014107f0ca1cff867b5f7565cb79d6684f9b35df](https://github.com/ClayAmore/ER-Save-Editor/tree/014107f0ca1cff867b5f7565cb79d6684f9b35df).
Credit ClayAmore and ER-Save-Editor contributors; MIT, full notice in `fixtures/LICENSE-MIT.txt`
and both archive input directories. Original bytes, including any BOM, are preserved in the zip.
Nothing from upstream is executed. Every input is checked against the production importer's
existing SHA-256 pins on each run.

- `names/`: `src/db/{weapon,item,armor,accessory,aow}_name.rs`, stored with the importer-required
  `src_db_` prefix, and `LICENSE-MIT`.
- `progress/`: `src/db/{graces,classes,event_flags,map_name,bosses,maps}.rs`, `src/util/bit.rs`,
  `src/vm/events.rs` and `LICENSE-MIT`.

The archive was assembled from the already reviewed local `r2/` and `completion/` scratch inputs.
It contains the complete pinned sets, including provenance-only inputs. Deterministic zip entry
timestamps avoid incidental archive metadata churn. The importers remain the authority for hashes.

## What the golden checks establish

| Pipeline | Byte-level comparison | Limit |
| --- | --- | --- |
| Progress | Regenerate all five files and compare every byte with the shipped manifest, both data files, MIT notice and provenance sidecar. Reject missing/extra files. | Git `text=auto` uses CRLF on Windows; only checked-out expected text is converted to its committed LF representation. Generated bytes are compared unchanged. |
| Base names | Regenerate all 12 files from the original pinned inputs. Compare the entire filename/SHA-256 map against the original importer baseline; independently compare the MIT notice to the shipped notice. | Shipped v3 data/manifest require the later visual step. Five shipped name sidecar footers were edited manually and differ from importer output. |
| Community | Run the real entry point on tiny original literal XML/Lua/Rust/block-map fixtures and two synthetic archives, then compare all six output files, including manifest, data, provenance and generated `CommunitySourceReferences.cs`. | Exact pinned TGA/Paramdex archives, inherited `items.rs` and sparse block-map input were absent in available scratch. Fixture-specific archive/input hashes replace pins only inside the test module; a separate test exercises rejection using real production pins. No claim of full shipped-pack regeneration. |
| Visual | Start with the full pinned base-name pack, then run the real entry point with small synthetic Compass TS/WebP fixtures. Compare all 18 final files: name data/manifest/sidecars, deduplicated icon, three maps, coordinates and summary. | The 1,000+ original Compass image/text inputs were absent. Tests characterize the encoder/stitching and joins, not regeneration of the 1,099 shipped images or all 597 placements. `visuals.source.md` is hand-authored and is not emitted by any importer. |

`*.sha256.json` files were captured from the **unmodified importers at 9a858ef**, before refactoring.
They pin both the complete file inventory and exact output-byte digests. Do not regenerate them
to make a refactor pass; inspect any mismatch. Image goldens include the actual encoded WebP bytes,
so the encoder versions are part of the characterization contract.

The synthetic community fixtures exercise precedence, sentinels, comment exclusion, sorted group
membership, repeated occurrences, base/DLC/NG+ groups, sparse addressing, unmapped events, technical
XML-only extraction, compaction and obsolete-dump removal. Visual fixtures exercise selection,
the reviewed goods punctuation alias, exact-name rejection, icon deduplication, all three map
layers, overworld tiers, nearest legacy basepoints, ambiguous/missing entities, conflicting
positions and out-of-bounds exclusion. Additional tests pin validation before output, bad image
signatures/dimensions, conflicting progress joins and whitespace preservation.

## Full manual regeneration limitations

The tests deliberately do not acquire missing inputs. For a full independent run, supply the exact
archives/loose sources pinned in `community_sources.py` and `import-community-catalog.py`, plus
every original file listed in `visual-inputs.json` (paths and optional `upstreamPath` identify the
source at Compass revision `be49e96b0513d8e08d22806b5b3fee9654e3e9de`). Preserve original bytes.
The original source URLs, hashes and attribution remain in the shipped source sidecars.

Run name import before visual enrichment, use the pinned Pillow/libwebp encoder, and separately
preserve the manually maintained `visuals.source.md` and five name sidecar footer updates.
Neither the old importer nor this refactor can reproduce those manual documentation changes.
No runtime resources are regenerated or changed by this work.
