## What was imported and changed

- 110 distinct icons: 64 skill icons, 37 item/equipment/progress category symbols,
  and 9 arte symbols matched to 59 named Alphen/Rinwell guide rows. Shared category
  symbols are intentional; they do not claim unique artwork for each item or arte.
- Icons on 1,660 records: 271 items, 675 equipment, 64 skills, 59 artes,
  463 skill-panel nodes and 128 progress guides. Missing matches keep a text fallback.
- 16 official localized arte-description transcriptions populate 18 playable arte
  records and seven matching panel nodes (25 description records). Only the explicitly
  labelled **Tales of Arise / Localized Description** section was used; quotations from
  other games, battle quotes and descriptions absent upstream were not substituted.
  The descriptions are wiki transcriptions, not independently verified game dumps.
- One 1200x675 Dahna story map, hosted by atwiki, converted intact to quality-78 WebP.
  It is **decorative behind the schematic**. No geographic alignment is established.
  Original 0..100 grid coordinates are scaled by (12, 6.75) into 1200x675 display bounds,
  preserving all 131 markers and the map aspect ratio. The schematic/text list survives
  unavailable artwork. All progress/save joins remain Unknown.
- Icons are at most 64x64, using lossless WebP or PNG-8 when smaller (9 PNG, 101 WebP).
  Identical encoded content shares one path; none of these 110 outputs is duplicated.
  Image decoding, validation and encoding happened outside the repository with Python -I
  and Pillow 12.2.0. Raw downloads and source HTML remain outside git.
- **185,302 new embedded image bytes**: icons **90,698**, map **94,604**.
  Every output and original download has an exact SHA-256 in `asset-sources.json`;
  all served files also have hashes in `pack.json`. The minified ledger contains exact
  record mappings, source URLs, description response hashes, dimensions and byte counts.
  Original F2 facts and IDs are preserved. No save format or writer was changed.

## Reproduction

Run `ReferenceData/build_assets.py --scratch <outside-repository-directory>` after the existing catalog builder. It re-fetches only pinned image URLs, rejects changed source bytes and unsupported image headers, applies the reviewed mappings, and verifies reproducible encoded hashes. A Pillow/libwebp change requires reviewing and deliberately updating the output pins. Attribution remains in this sidecar, the README, Info.References, catalog details and the Sources/map attribution panels.
